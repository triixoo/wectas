# Wectas

Блокчейн-стартап из Казахстана. Текущая версия — инструмент для ограниченного пилота цифровых паспортов партий с ручным сопровождением. Сервер не используется по запросу владельца.

## Что работает

Создание партии; локальная библиотека и поиск; версии истории; добавление событий производителя, перевозчика, покупателя и лаборатории; импорт/экспорт JSON; сжатая публичная ссылка; QR и печатная этикетка. После изменения паспорта нужен новый QR. Старые ссылки не обновляются и не отзываются.

Подписи событий ECDSA P-256 проверяются локально. Закрытые ключи сохраняются зашифрованными AES-GCM с PBKDF2-SHA-256 (600 000 итераций), разблокируются только в текущей вкладке и никогда не входят в публичный паспорт. Ключ можно экспортировать и импортировать, пароль восстановить нельзя. Отпечатки участников сверяются вручную по независимому каналу; владение ключом не равно проверенной личности. Это не государственная ЭЦП.

До пяти документов по 5 МБ на событие сохраняются только в IndexedDB этого браузера. Публичный паспорт содержит тип и SHA-256 байтов, без имени и содержимого файла. Полученный отдельно документ можно сверить с хешем. Совпадение не подтверждает правдивость содержания. Локальные документы скачиваются или удаляются отдельно.

Зашифрованная резервная копия содержит версии, документы, защищённые ключи и сверенные отпечатки; переносится на другое устройство вручную. Восстановление сначала проверяет весь файл, затем выполняет атомарное добавление. Пароль копии и пароли ключей независимы. Очистка браузера удаляет кабинет; никакой удалённой копии нет. Публичные данные паспортов и документы в локальном кабинете не шифруются, закрытые ключи и скачанная резервная копия шифруются.

Заявка готовит черновик сообщения для Telegram @kashyyn. Нажатие «Открыть чат» передаёт текст Telegram, а отправку клиент подтверждает сам. Копирование текста и скачивание брифа доступны как запасной путь. Сайт не утверждает, что сообщение доставлено, и не хранит заявки.

## Тестовое закрепление

Для версии 2 реализован запрос к браузерному Ethereum-кошельку: транзакция на свой адрес, сумма 0, данные — `WECTAS-V2:` + SHA-256 текущей версии. Разрешена только Sepolia (`0xaa36a7` / 11155111); нужен тестовый ETH для комиссии. Приложение не хранит ключи кошелька и не отправляет транзакции автоматически.

Транзакционный хеш в файле — ссылка на проверку. Кнопка «Проверить в сети» сравнивает входные данные, адрес, сумму, статус receipt и наличие транзакции в каноническом блоке через RPC кошелька, отдельно сообщает финализацию. Якорь старой версии подтверждает только её префикс. Нет фоновых сетевых запросов, собственного RPC или сервера. Пользователь доверяет провайдеру своего кошелька. Нужен кошелёк с поддержкой этих JSON-RPC методов.

**Реальную транзакцию разработчик не отправлял:** нет подключённого кошелька с тестовым ETH. Отправка и проверка покрыты RPC-фикстурами; браузер проверяет блокировку основной сети. Не выдавать это за подтверждённый промышленный блокчейн-сервис.

Технические первоисточники, проверены 7 октября 2026: [EIP-1193](https://eips.ethereum.org/EIPS/eip-1193), [Ethereum JSON-RPC](https://ethereum.org/developers/docs/apis/json-rpc/), [Sepolia](https://github.com/eth-clients/sepolia), [Web Crypto: подпись](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/sign), [Web Crypto: deriveKey](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/deriveKey), [IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API), [Telegram draft links](https://core.telegram.org/api/links#public-username-links).

## Запуск и проверки

Статические HTML/CSS/JS, без Next.js и установки зависимостей. `npm run dev`: http://127.0.0.1:4173. `npm test`: схемы, хеши, подписи, подмена данных с пересчётом цепочки, шифрование, копии, ссылки, документы и RPC-фикстуры. Версия 1 сохранена для чтения старых демонстраций; новые реальные партии используют версию 2.

Chrome QA: создание и подписанный обмен между двумя независимыми браузерными контекстами, сохранение после перезагрузки, документы, восстановление в чистом браузере, ошибочные файлы, заявки, мобильная вёрстка. Не проводился независимый аудит безопасности или проверка всех браузеров.

## Коммерческие границы

Нет общего сервера, аккаунтов, синхронизации, постоянных коротких ссылок, прав доступа между компаниями, проверки юридических лиц, онлайн-оплаты, промышленного SLA и подтверждённого спроса. Роли описывают события, не ограничивают доступ к файлу. Пилот, цена и оплата согласуются лично. Продавать конкретный объём работы и сопровождение; не обещать сертификацию, гарантию происхождения или готовность SaaS.

## Публикация и мониторинг

GitHub Pages публикует `dist/` после успешных тестов на main. Pull requests проходят проверки без публикации. Каждую неделю около понедельника 10:00 Алматы Market watch проверяет шесть первоисточников, сохраняет статус и создаёт/обновляет issue. Расписание может задерживаться или отключиться в неактивном репозитории. Сигнал изменения страницы не является подтверждённым фактом или автономной разработкой. API-ключей агента нет.
